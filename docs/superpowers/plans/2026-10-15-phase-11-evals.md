# Phase 11 Evals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make explanation-path integrity, held-out role accuracy, and current-versus-retired prompt quality measurable through repeatable LangSmith evaluations.

**Architecture:** Keep the invented-path check pure and deterministic in `lib/evals`; the existing explanation tasks invoke a traced live adapter after every answer. Scripts load the same environment as Next, build their datasets from existing Supabase analyses, and publish role and prompt experiments to LangSmith. The retired prompt exists only under `evals/`.

**Tech Stack:** TypeScript, Node test runner, `@next/env` via Next 16.3.6, OpenAI SDK, LangSmith 0.10.5, Supabase JS.

**Spec:** `docs/superpowers/specs/2026-10-15-phase-11-evals-design.md`

## Global Constraints

- Invented-path scoring is exact set membership; no model grades paths.
- A live explanation must be evaluated whether it was a cache hit or miss, and evaluator failure cannot suppress its answer.
- Role examples must have a convention role contained in `MODEL_ROLES`; reject a dataset below 30 examples.
- The retired explanation prompt lives under `evals/` and must not be imported by application modules.
- The prompt comparison uses one frozen dataset for both versions and labels the model-judge metric as subjective.
- Secrets remain server-only; scripts load `.env*` with `@next/env` before importing modules that read environment variables.

## Review Focus

- Backticked non-path code such as `` `map()` `` is ignored, while a made-up repository filename is reported.
- A duplicate invented filename appears once in failures rather than inflating the count.
- A folder explanation's allowed set includes member and crossing-edge paths, not only its directory name.
- A structural convention role is excluded from role accuracy even when it has valid source text.
- An unavailable historical source or a judge failure is visible in the script output and excluded from its denominator, not misreported as a bad model answer.

---

## File structure

- `lib/evals/invented-paths.ts`: pure path extraction, allowed-path derivation, and deterministic score.
- `lib/evals/live.ts`: traced best-effort adapter from live explanation tasks to the deterministic evaluator.
- `lib/evals/role-dataset.ts`: pure eligibility/filtering and percentage aggregation for convention-held-out examples.
- `scripts/env.ts`: one-time `loadEnvConfig(process.cwd())` entry point for standalone scripts.
- `scripts/eval-invented-paths.ts`: query recent live LangSmith explanation runs and print deterministic score plus failures.
- `scripts/eval-role-accuracy.ts`: construct at least 30 valid held-out examples and run a LangSmith experiment.
- `scripts/eval-prompts.ts`: read the frozen JSONL data, run current and retired versions, and publish comparative judge results.
- `evals/prompts/explain-file.v1.ts`: the previously shipped v1 prompt constants/message builder only.
- `evals/datasets/explain-file.v1.jsonl`: checked-in frozen comparison inputs, with no secrets or full repository source beyond existing sample fixtures.
- `test/evals/*.test.ts`: Node test-runner coverage for deterministic logic and dataset eligibility.
- `package.json`: Node test and three evaluation script entries.
